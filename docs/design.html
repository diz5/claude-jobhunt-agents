claude-jobhunt-agents

A multi-agent job-hunt workspace: skills route the work, subagents do the judgment, deterministic scripts own the bookkeeping — and a hard boundary keeps every piece of your real data out of the public repo.

8 agents · 3 skills · 6 scripts public tooling · private data LLM for judgment · code for mechanics

Two principles hold it together

Every design choice below descends from one of these.

LLM for judgment · code for mechanics

Research and scoring need reasoning → they run in subagents. Sorting, de-duping, merging the board are deterministic → they run in Python: exact, atomic, race-free, sub-second.

Public tooling · private data

The tooling is git-tracked and public. Your real data lives only in gitignored files the tooling reads locally. Nothing personal is ever committed.

the ranked master board
The board pipeline. New rows are appended to a _pending.md staging buffer, then merged into the board in one atomic flush — so concurrent sessions never clobber it. On the way in, a hard min-score gate drops anything scoring < 6, ties share a rank, and every mutation stamps .board-state.json so a long-running session can refresh and re-read instead of reasoning from stale memory. Each flush appends an audit line to .merge-log.md — recording the session id (captured automatically from $CLAUDE_CODE_SESSION_ID) and merge counts for concurrent-session visibility.

Public vs private — the boundary

The .gitignore + publish_guard.py + a pre-commit hook form a one-way membrane: tooling flows out, data never does.

The components

All public. Personal specifics never live here — every one reads them from the private files at runtime.

skill Playbooks ×3

  • analyze-job
    Orchestrator: dedup, analyze, batch, application answer, status, refresh, source, status report.
  • interview-prep
    Recruiter/HR screen: interactive mock + prep-pack generation.
  • list-sessions
    Lists past Claude sessions for the project.

agent Agents ×8

  • job-sourcer
    Proactively scans ATS job boards for new postings matching the candidate's profile; returns ranked shortlist.
  • job-analyzer
    Researches + scores one posting → ⭐ report + row.
  • application-answerer
    Drafts a short, human application answer from the analysis + kit.
  • interview-prep-writer
    Writes one company's recruiter-screen pack.
  • interview-intel
    Researches recent interview experiences for one company × stage.
  • publish-guard
    Read-only leak check before publishing.
  • design-doc-writer
    Keeps this design page in sync — surgical, low-cost.
  • role-scout
    Scouts a company's careers page/ATS for better-fitting roles.

script Mechanics ×6

  • scoreboard.py
    Owns every board write — deterministic, atomic.
    append flush status refresh remove prune state check
  • batch_summary.py
    End-of-batch chart: parses analysis files' template and prints standardized fit/salary/risk scores per job.
  • status_report.py
    Job-hunt snapshot — funnel counts, deltas vs previous run, interviews, score bands, top unapplied.
  • publish_guard.py
    Secret scanner; exit ≠ 0 blocks the commit.
  • list_sessions.py
    Backs the list-sessions skill.
  • web_budget_guard.py
    PreToolUse hook — hard-caps WebSearch/WebFetch calls per session.
